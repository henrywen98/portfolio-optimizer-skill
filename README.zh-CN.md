# asset-allocation

一个 Claude Code skill：把「我有多少钱、大概能承受多少亏损」变成具体到 ETF 代码和权重的组合，
并且验证那个「能承受多少」的承诺到底站不站得住。

面向 A 股散户，覆盖 A 股宽基、国债、黄金、海外权益（QDII），全部用场内 ETF。

## 和别的组合工具有什么不一样

多数工具优化夏普比率然后报一堆回测数字。这里处理了两个它们不处理的问题。

**1. 回撤约束没有解析解。** 最大回撤不是权重的凸函数，写不出公式，只能把权重放进真实价格
序列跑一遍。所以这里用网格搜索，逐个候选回测，只留守住预算的那些。

**2. 一次实现的回撤不是分布。** 组合在某条历史路径上恰好录得的最大回撤，是有效样本量为 1
的单次抽样。拿它当硬上限是乐观的。所以约束卡的是**平稳区块自助分布的 95 分位**，不是实现值——
这是默认行为。

差多少？用 2014-2026 的 A 股数据实测：

| 组合 | 实现最大回撤 | 自助 p95 |
|---|---|---|
| 国债25% 纳指25% 沪深300 20% 黄金20% 红利10% | -19.2% | **-25.5%** |
| 全仓沪深300 | -47.1% | **-72.0%** |

实现值大约乐观 6 个百分点。另外注意沪深300 的自助 p95 是 **-72.0%**，而它 2008 年的真实
回撤是 -72.3%——那次崩盘根本不在样本窗口里。

## 守不住就报错，不糊弄

- 没有任何组合能满足你的回撤预算时，直接报错并告诉你最保守的组合还要回撤多少。
  **绝不悄悄放宽约束凑一个结果出来。**
- 回测窗口盖不住 2015 年那波 A 股暴跌时，拒绝运行。只在牛市数据上标定的回撤上限是假承诺。

## 不做预测

不选赛道、不择时、不写「本季度看好 AI 算力」。权重由风险预算决定。网络搜索只用来决定
一次性建仓还是分批，以及写风险提示那一段。

```bash
git clone https://github.com/henrywen98/asset-allocation.git \

```

## 用法

```bash
# 1. 拉历史行情（纯标准库，不用装任何东西）
python3 scripts/fetch_history.py \
  --codes 510300,510500,510880,511010,518880,513100 \
  --start 2014-01-01 --out data/core_prices.csv

# 2. 在回撤预算下求权重
python3 scripts/allocate.py \
  --prices data/core_prices.csv \
  --specs core_specs.json \
  --max-dd 0.20 \
  --horizon-years 5
```

`allocate.py` 需要 pandas 和 numpy，`fetch_history.py` 什么都不需要。

或者直接跟 Claude Code 说：「帮我配个资产组合，最多能亏 20%」。

## 输出

- `weights` — 各 ETF 目标权重
- `metrics` — 年化、波动、夏普、实现最大回撤
- `robustness` — 把窗口切成三段逐段复核，只在某一段成立的组合会被标出来
- `holding_period` — 持有 N 年的收益分布和亏钱概率。期限短的时候这个比最大回撤重要得多
- `frontier` — 各回撤档位能拿到的最高收益，让你看清放宽预算到底换来什么

## 数据源

腾讯行情接口 `web.ifzq.gtimg.cn`，免 key、不封 IP、前复权。东财的历史接口不作主源——
它在部分网络下会被 DNS 解析到黑洞地址。
