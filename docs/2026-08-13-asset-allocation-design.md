# asset-allocation skill 设计

2026-08-13

## 要解决的问题

Henry 想要一个可重复使用的工具：说清自己的本金和能承受的亏损，得到一份具体到 ETF 代码和权重的资产组合，外加一份说明为什么这么配的报告。以后还能拿它复查持仓漂移、决定要不要再平衡。

不是取数工具，也不是选股工具。是**编排 + 约束校验**：把「风险承受力」翻译成「大类权重」，并且证明这个权重在历史上真的守住了承诺的回撤。

## 核心原则

**被动为主，不预测涨跌。** 组合由风险约束决定，不由对后市的判断决定。网上的市场资讯只用来回答「现在一次性建仓还是分批」和「有什么风险要提示」，不用来调整目标权重。

理由：主动方向判断的输出无法验证，也无法回测。一份读着专业但预测能力为零的报告，比没有报告更有害——它会让人以为自己有依据。

**回撤约束靠回测算，不靠公式估。** 「最大回撤 ≤ 20%」没有解析解。流程必须是：生成候选权重 → 在真实历史序列上回测 → 算出真实回撤 → 剔除超标的 → 在合规的组合里选收益最高的。

**守不住就说守不住。** 如果所有候选组合的历史回撤都超过用户设的上限，脚本报错并说明「最保守的组合历史回撤也有 X%」，让用户选择放宽约束或降低预期。**不返回一个假装合规的组合。**

## 流程

```
1. 风险画像    → 问卷（能力 + 意愿），取低者
2. 定大类比例  → 四类资产 + 卫星仓
3. 拉历史数据  → akshare，缓存 CSV
4. 算权重+校验 → 回测筛选，回撤硬约束
5. 搜当前市况  → WebSearch，只影响建仓节奏
6. 出报告+存档 → markdown 报告 + profile 档案
```

### 1. 风险画像

风险承受力必须拆成两个维度分别问，这是 CFA 体系里的标准做法（参考 JoelLewis/finance_skills 的 investment-policy）：

- **意愿**（心理承受）：最多能忍受多少浮亏而不失眠、不割肉。
- **能力**（财务承受）：这笔钱多久不用、收入稳不稳、有没有独立的应急金、本金占总资产多大比例。

**两者冲突时取低的那个**，并在报告里写明按哪个来、为什么。一个说自己能扛 50% 但三年后要用这笔钱买房的人，实际能力上限远低于 50%。

### 2. 大类资产菜单

| 大类 | 角色 | 权重范围 |
|------|------|----------|
| A股宽基 | 收益来源 | 由约束决定 |
| 债券 | 压回撤 | 由约束决定 |
| 黄金 | 分散（与 A 股低相关） | 0-20% |
| 海外权益 QDII | 分散 | 0-25% |
| A股行业/主题 | 卫星 | 合计 ≤ 20% |

行业/主题 ETF 单独限制在 20% 以内。被动配置下它们波动远高于宽基，放开会直接顶穿回撤约束。

具体 ETF 代码见 `references/asset-menu.md`。每个都必须用真实数据验证存在、有足够历史、流动性够。

### 3. 数据

`scripts/fetch_history.py`，用 akshare 取场内 ETF 日线，缓存到 `data/`。

**硬性要求：回测窗口必须覆盖 2015 和 2018 两次 A 股大跌。** 数据起点不够早，回撤约束就是假的——只在牛市数据上回测出来的「最大回撤 15%」毫无意义。脚本对此做校验，窗口不够直接报错，不出结果。

**实现时修正的一条**：原计划「ETF 成立晚于 2014 的用指数序列补齐」，核实后放弃。行业主题
ETF 最早的（512880 证券、512660 军工）是 2016-08 上市，而中证全指证券公司(399975)、
中证医疗(399989)、中证白酒(399997) 这几个**指数本身**是 2015 年 9-10 月才发布的——2015 年
6 月的数据在任何层面都不存在，补不了。

改成：行业主题不进核心优化，按规则硬限制合计 ≤ 20%，报告里写明这部分不受回撤约束保护。
比拼接干净——拼接会把跟踪误差、费率、溢价混进历史序列。

### 4. 权重求解

在满足约束的权重网格上回测，取夏普最高者。约束：

- 各大类权重上下限（见上表）
- 权重和为 1
- **历史最大回撤 ≤ 用户设定的上限**（硬约束，不可放松）

用网格搜索而不是凸优化，因为回撤不是权重的凸函数，而且资产只有 6-8 个，网格完全够用。副作用是不需要 cvxpy 这类重依赖。

**目标函数用最大化年化收益，不是最大化夏普。** 实现时先写成夏普最优，实测发现问题：20% 的
回撤上限下，夏普最优解只回撤 4.2%、年化 7.2%——它系统性地用不满用户明确授权的风险预算。
用户说能承受 20%，意思是愿意拿这 20% 换收益。改成收益最优后是回撤 19.7%、年化 14.7%。

**代价是过拟合风险。** 「在合规组合里选历史收益最高」本质上就是买过去这段窗口涨得最好的资产。
所以必须配两个补丁：

- **子区间检验**：把窗口等分成 3 段，逐段复核回撤。某段破了上限就在报告里明确警告——
  全窗口达标可能只是被某一段的大涨稀释了。
- **输出回撤-收益前沿**：各回撤档位能拿到的最高收益。这张表让用户自己判断多冒险划不划算，
  而不是只接受一个被优化器选中的点。实测这条曲线在 35-40% 处见顶后下降。

### 5. 市场资讯

WebSearch 查两件事：主要宽基当前估值分位、近期宏观风险事件。

**只影响两个输出**：建仓节奏（一次性 vs 分 N 期）和报告里的风险提示段落。**不改变第 4 步算出的目标权重。**

### 6. 输出

- **报告**：markdown，含目标权重表、每类资产的理由、回测指标、压力情景、建仓计划、再平衡规则。
- **档案**：`portfolio-profile.json`，存风险画像、目标权重、本金、持仓。含个人财务数据，**不进任何 git 仓库**。

报告必须包含压力情景：「如果重演 2008，这个组合大约亏 X%」。沪深300 在 2008 年回撤 72%，而回测窗口（2014 起）不含这一段。只报回测回撤会系统性低估尾部风险。

## 环境

`uv venv --python 3.12`，装 pandas / numpy / akshare。不改系统默认 Python。

## 测试

`test_allocate.py` 用构造的价格序列验证三件事：

1. 回撤计算正确（给已知序列，比对手算结果）
2. 超标组合确实被剔除（构造一个必然超标的资产，确认它不出现在结果里）
3. 全部候选超标时报错，而不是返回结果

## 不做的事

- 不预测涨跌，不选赛道
- 不做个股，只做场内 ETF
- 不接券商接口，不下单
- 不算税（A 股 ETF 个人投资者免所得税，印花税场内 ETF 免征，只有佣金）

## 已知局限（报告里要写明）

- 历史回撤不是未来上限。2008 级别的下跌不在回测窗口内。
- 相关性在危机时会一起冲向 1，分散效果在最需要的时候最弱。
- QDII 有溢价和限额风险，溢价高时买入等于多付钱。
- 静态权重 + 定期再平衡，不含任何择时。
